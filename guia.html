Qué es este ejercicio

No es un ejercicio de lógica como el 9.1 o 9.5. Es un dashboard: una página índice que enlaza a todos tus ejercicios de repaso funciones, muestra tu progreso con cuadraditos verdes y guarda qué ejercicios ya visitaste.

Usuario abre dashboard → clic en ejercicio → se guarda en localStorage → enlace verde + cuadradito verde + contador actualizado

Qué hace cada parte

  • index.html — estructura visual: foto, listas de ejercicios, panel historial.
  • historial.js — biblioteca: leer/guardar progreso, generar HTML de cuadraditos.
  • dashboard.js — conecta HTML con biblioteca; refrescar es la función principal.

Conceptos que debes dominar

1. Biblioteca vs función principal

Biblioteca (historial.js): solo entrada → salida. Sin document, sin getElementById. Como esPrimo() en 9.1.

Función principal (refrescar en dashboard.js): lee datos → llama biblioteca → escribe en HTML. Como funcionMain en 9.5.

Ejecución: los addEventListener conectan clics con biblioteca y luego llaman a refrescar.

2. Texto del enlace vs ruta (href)

Parte Ejemplo Para qué sirve
Texto visible 9.2 · Recortar texto Lo que lees tú (nombre del ejercicio)
href 9.02-repaso-funciones/index.html Ruta real a la carpeta en disco

El href no puede ser el título del ejercicio porque esa carpeta no existe. Debe coincidir exactamente con el nombre de la carpeta.

3. Rutas sin espacios (kebab-case)

Las carpetas se llaman 9.01-repaso-funciones, 9.02-repaso-funciones… con rayas y cero delante en el 9.1–9.9 para que GitHub las ordene bien (9.01, 9.02… 9.10, 9.11).

4. ¿Se puede hacer solo con funciones biblioteca?

Casi, pero no al 100 %. Toda la lógica (guardar, contar, generar strings HTML) puede estar en biblioteca. Pero algo tiene que buscar elementos del DOM y registrar clics. Eso es ejecución + main, no biblioteca.

5. localStorage y data-id

  • CLAVE = "repaso-funciones-historial" — nombre bajo el que se guarda la lista en el navegador.
  • data-id="9.2" en cada enlace — identificador del ejercicio para el historial (no confundir con href).
  • Al clic: alClicEjercicio(CLAVE, "9.2") → guarda → refrescar() repinta todo.

Funciones biblioteca — código completo y reutilización

Este cuadro contiene todo historial.js listo para copiar. Ninguna línea usa document.

historial.js — código completo

const leerHistorial = (clave) => {
  try {
    return JSON.parse(localStorage.getItem(clave) || "[]");
  } catch {
    return [];
  }
};

const guardarHistorial = (clave, lista) => {
  localStorage.setItem(clave, JSON.stringify(lista));
  return lista;
};

const agregarVisita = (lista, id) => {
  if (lista.includes(id)) return lista;
  return [...lista, id];
};

const vaciarHistorial = () => [];

const alClicEjercicio = (clave, id) =>
  guardarHistorial(clave, agregarVisita(leerHistorial(clave), id));

const alReiniciar = (clave) =>
  guardarHistorial(clave, vaciarHistorial());

const textoContador = (lista, total) =>
  `Visitado: ${lista.length} / ${total}`;

const clasesEnlace = (id, lista) =>
  lista.includes(id)
    ? "exercise-link text-[#39ff14] font-semibold hover:underline"
    : "exercise-link text-cyan-300 hover:underline";

const htmlCuadrito = (id, lista) => {
  const hecho = lista.includes(id);
  const base = "flex aspect-square items-center justify-center rounded text-[0.5rem] font-bold";
  const verde = "bg-[#39ff14] text-black";
  const gris = "border border-white/15 bg-white/10 text-white/40";
  return `<div class="${base} ${hecho ? verde : gris}">${id}</div>`;
};

const htmlCuadritos = (ids, lista) =>
  ids.map((id) => htmlCuadrito(id, lista)).join("");

Cada función — entrada, salida y dónde reutilizarla

leerHistorial(clave)

Entrada: string. Salida: array de ids visitados.

Reutilizar en: cursos online, checklist, niveles de juego, capítulos leídos.

guardarHistorial(clave, lista)

Entrada: clave + array. Salida: lista guardada.

Reutilizar en: borradores, preferencias sin backend, «continuar donde lo dejaste».

agregarVisita(lista, id)

Entrada: lista + id. Salida: lista sin duplicados.

Reutilizar en: lecciones completadas, logros, pasos de wizard.

vaciarHistorial()

Salida: [].

Reutilizar en: botón «Empezar de cero», reset de progreso.

alClicEjercicio(clave, id)

Reutilizar en: índice de capítulos, menú de módulos, grid de retos.

alReiniciar(clave)

Reutilizar en: panel ajustes, reiniciar progreso en apps educativas.

textoContador(lista, total)

Reutilizar en: «3 de 10 leídos», contadores de misiones.

clasesEnlace(id, lista)

Reutilizar en: menús con ítems completados en otro color.

htmlCuadrito y htmlCuadritos

Reutilizar en: mapas de niveles, grids de logros, calendarios de hábitos.

Test — 15 preguntas

Haz clic en cada pregunta para ver la respuesta. Intenta responder antes de abrir.

▶ 1. ¿Cuál es la función principal de este proyecto y en qué archivo está?
La función principal es refrescar y está en assets/js/dashboard.js. Hace el papel de funcionMain en los ejercicios 9.x: coordina la lectura del historial, llama a funciones de biblioteca y escribe el resultado en el HTML (enlaces, cuadraditos y contador). No es biblioteca porque usa document, getElementById y elementos concretos de esta página.
▶ 2. ¿Por qué hay dos archivos JS en lugar de uno solo?
Para separar responsabilidades como pide el curso. historial.js contiene solo lógica reutilizable (biblioteca): datos, localStorage, strings HTML. dashboard.js contiene lo específico de esta página: variables del DOM, la función principal refrescar y los listeners. Así puedes copiar historial.js a otro dashboard sin tocar la biblioteca.
▶ 3. ¿Para qué sirve data-id="9.2" en un enlace?
Guarda el identificador del ejercicio para el historial. Cuando haces clic, JS lee enlace.dataset.id (devuelve "9.2") y lo pasa a alClicEjercicio. Es independiente del href: el href dice dónde navegar; el data-id dice qué id guardar en localStorage.
▶ 4. ¿Qué es CLAVE y por qué no usar un texto cualquiera en cada sitio?
CLAVE = "repaso-funciones-historial" es el nombre único bajo el cual se guarda la lista de visitados en localStorage. Si cada función usara un string distinto, leerían y escribirían en sitios diferentes y el historial no funcionaría. Centralizarla en una constante evita errores de tipeo y facilita cambiar el nombre en un solo sitio.
▶ 5. ¿Por qué el texto del enlace dice «Recortar texto» pero el href dice «9.02-repaso-funciones»?
Porque son cosas distintas. El texto visible es el nombre del ejercicio para el usuario. El href es la ruta real al archivo en disco. Las carpetas se crearon con nombres tipo 9.02-repaso-funciones, no con el enunciado completo. El navegador necesita la ruta exacta para encontrar index.html dentro de esa carpeta.
▶ 6. ¿Qué pasa paso a paso cuando haces clic en el ejercicio 9.3?
1) Se dispara el listener de click en ese enlace. 2) Se ejecuta alClicEjercicio(CLAVE, "9.3"): lee el array actual, añade "9.3" si no estaba, guarda en localStorage. 3) Se llama a refrescar(): vuelve a leer el historial, pone el enlace 9.3 en verde, pinta cuadraditos y actualiza el contador. 4) El navegador navega al href del enlace (9.03-repaso-funciones/index.html).
▶ 7. ¿Por qué usamos getElementsByClassName y un for?
Es el estilo pedido para este proyecto: primero getElementById("lista-ejercicios"), luego getElementsByClassName("exercise-link") y bucle for clásico. Funcionalmente es equivalente a querySelectorAll + forEach, pero deja claro el vínculo con el HTML.
▶ 8. ¿Qué devuelve htmlCuadritos(ids, visitados) y quién lo escribe en pantalla?
Devuelve un string HTML con los 21 divs de los cuadraditos (verdes los visitados, grises los pendientes). No escribe en pantalla por sí sola: es biblioteca. refrescar (función principal) hace grid.innerHTML = htmlCuadritos(ids, visitados) para insertarlo en #history-grid.
▶ 9. ¿Por qué los scripts están al final del body?
Porque dashboard.js usa getElementById en cuanto se carga. Si el script estuviera en el head, el HTML del ul, el grid y el botón aún no existirían y las variables serían null. Al poner los scripts al final, todo el DOM ya está creado. Además, historial.js debe ir antes que dashboard.js.
▶ 10. ¿Qué hace refrescar() la primera vez, al cargar la página?
La última línea de dashboard.js es refrescar(); sin listener. Al cargar, lee localStorage (puede estar vacío o tener visitas anteriores), colorea los enlaces ya visitados, dibuja los cuadraditos y pone el contador correcto. Así el usuario ve su progreso guardado sin tener que hacer clic primero.
▶ 11. ¿Todas las funciones de historial.js son biblioteca al 100 %?
Sí, en el sentido del curso: ninguna usa document, getElementById ni addEventListener. Reciben datos por parámetros y devuelven datos (array, string, HTML string). clasesEnlace y htmlCuadrito devuelven strings con clases Tailwind de este diseño; si cambias de framework CSS, ajustarías esas cadenas, pero la lógica sigue siendo reutilizable.
▶ 12. ¿Qué hace el botón «Reiniciar historial» por dentro?
El listener llama a alReiniciar(CLAVE), que ejecuta guardarHistorial(clave, vaciarHistorial()) — guarda un array vacío [] en localStorage sobrescribiendo el historial anterior. Luego llama a refrescar(): todos los enlaces vuelven a cyan, todos los cuadraditos a gris y el contador muestra Visitado: 0 / 21.
▶ 13. ¿Por qué las rutas usan rayas (9.02-repaso-funciones) en lugar de espacios?
Para tener URLs y rutas sin espacios. Con espacios el navegador puede codificarlos como %20, que es menos legible. Las rayas (kebab-case) son la convención habitual en web, evitan problemas al copiar enlaces y coinciden con nombres de carpeta limpios en disco. Importante: el href debe coincidir exactamente con el nombre real de la carpeta renombrada.
▶ 14. Nombra las cuatro secciones de dashboard.js según la guía del curso.
1) Importación de módulos — comentario indicando que historial.js se carga en el HTML.
2) Declaración de variables — CLAVE, TOTAL, ids y los cuatro getElementById.
3) Declaración de funciones — refrescar (función principal).
4) Ejecución de código — bucles con addEventListener y la llamada inicial a refrescar().
▶ 15. ¿En qué tipo de páginas puedes reutilizar historial.js sin cambiar la lógica?
En cualquier página que necesite recordar qué ítems el usuario ya visitó o completó usando localStorage: índice de lecciones, checklist de tareas, mapa de niveles, grid de logros, lista de capítulos de un curso, portfolio con proyectos «vistos». Solo cambias en el dashboard específico: la CLAVE, la lista de ids, los ids del HTML y las clases CSS si el diseño es distinto. La biblioteca de lectura/escritura y conteo se copia igual.
