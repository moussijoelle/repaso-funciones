Guía del ejercicio 9.5 — Invertir palabras

Abrir la aplicación · Enunciado: miFuncion("Hola Mundo") → "odnuM aloH"

Enunciado Pizarra del profe ¿Independientes? Estructura JS HTML línea a línea JS línea a línea Biblioteca reutilizable Test (15 preguntas)

Enunciado del ejercicio

Programa una función que invierta las palabras de una cadena de texto.

miFuncion("Hola Mundo") → "odnuM aloH"

Qué ocurre (dos pasos)

  1. Cada palabra se lee al revés letra por letra: Hola → aloH, Mundo → odnuM.
  2. El orden de las palabras se invierte: primero va la que era la última.
"Hola Mundo"
  → separar     [ Hola ] [ Mundo ]
  → invertir    [ aloH ] [ odnuM ]
  → orden       [ odnuM ] [ aloH ]
  → unir        "odnuM aloH"

La pizarra del profe (dos mundos)

Izquierda — Biblioteca (como cuentaCaracteres o miFuncion):

  • Solo entradas (parámetros) y salida con return.
  • Sin document, sin getElementById.
  • Copiar y pegar en otro ejercicio sin cambiar el código.

Derecha — Función main + formulario:

  • Lee el input
  • Validación JS
  • Llama a la función pertinente
  • Recibe la respuesta
  • Escribe en HTML

El addEventListener solo dispara el main cuando el usuario hace clic.

¿Todas las funciones son independientes 100 %?

No. Y es normal. Lo que pide el curso es separar bien las capas.

Función ¿Independiente 100 %? ¿Copiar sin cambiar dentro?
invertirPalabra Sí Sí — solo string → string
miFuncion Sí Sí — prueba: miFuncion("Hola Mundo")
leerTexto No (usa DOM) Sí el código; en otra página pasas otro input
mostrarTexto No (usa DOM) Sí el código; pasas otro elemento

Frase para clase: La lógica del ejercicio (miFuncion) es independiente. La web siempre necesita código que lea inputs y escriba en pantalla; eso no puede ser 100 % puro sin HTML.

Estructura de app.js (siempre igual)

  1. Declaración de variables — getElementById (enlaces con el HTML).
  2. Declaración de funciones — biblioteca + ayudantes + funcionMain.
  3. Ejecución de código — addEventListener.
Usuario → clic → funcionMain
  → leerTexto
  → validación (vacío)
  → miFuncion
  → mostrarTexto → pantalla
Un solo archivo

Todo puede ir en app.js. El bloque biblioteca va arriba; lo copias a otro ejercicio sin modificarlo.

Funciones del lenguaje (no personalizadas) usadas

split, reverse, join, map, trim — ya vienen en JavaScript; tú no las inventas, solo las usas dentro de tu biblioteca.

Funciones biblioteca — reutilizar y en qué ejercicios

Biblioteca = entrada clara, return salida, sin buscar elementos del HTML dentro.

invertirPalabra(palabra)

Entrada: un string (una palabra). Salida: string con letras invertidas.

Reutilizar en: palíndromos, invertir un solo token, ejercicios de cadenas letra a letra, validar si una palabra se lee igual al revés.

miFuncion(cadena)

Entrada: frase completa con espacios. Salida: frase con cada palabra invertida y orden de palabras invertido.

Reutilizar en: solo este enunciado (9.5). En consola: miFuncion("Hola Mundo") sin abrir la web.

Páginas web: cualquier app donde el usuario escriba una frase y quieras mostrar la versión «espejo por palabras» (juegos de texto, retos, demostraciones en clase).

leerTexto(input) — ayudante (no biblioteca pura)

Copiar igual en: formularios de nombre, buscador, comentarios, cualquier <input type="text"> o textarea (con pequeño ajuste si es textarea: value igual).

mostrarTexto(elemento, texto) — ayudante

Copiar igual en: calculadoras, contadores de caracteres, resultados de exámenes, mensajes de error, preview de texto.

funcionMain — plantilla del profe

No copies ciegamente: en otro ejercicio sustituyes miFuncion por cuentaCaracteres, repetir texto, etc. La estructura Lee → valida → llama → escribe se repite.

Test — 15 preguntas

Haz clic en cada pregunta para ver la respuesta. Intenta responder antes de abrir.

▶ 1. ¿Qué debe devolver miFuncion("Hola Mundo")?
Debe devolver exactamente el string "odnuM aloH" (con un espacio entre las dos palabras invertidas). Cada palabra tiene las letras al revés y el orden de las palabras también se invierte. No debe haber espacios extra al principio ni al final si la entrada se pasa ya recortada con trim en el main.
▶ 2. ¿Qué hace invertirPalabra("Mundo")?
Devuelve "odnuM". Usa split("") para convertir el string en array de letras, reverse() para invertir ese array y join("") para volver a unirlas en un string. Es la pieza pequeña que miFuncion aplica a cada palabra con map.
▶ 3. ¿Por qué después de map se hace .reverse() en el array de palabras?
Porque el enunciado pide invertir cada palabra y además cambiar el orden de las palabras. Primero obtienes [aloH, odnuM] y con reverse() pasas a [odnuM, aloH]. Sin ese segundo reverse solo tendrías "aloH odnuM".
▶ 4. ¿Qué función es independiente al 100 % según el profe?
invertirPalabra y miFuncion: solo reciben strings, devuelven string con return, no usan document ni getElementById. Puedes probarlas en la consola del navegador sin tener HTML. funcionMain no es independiente porque coordina la página.
▶ 5. ¿Por qué getElementById solo está en las variables y no dentro de miFuncion?
Para que miFuncion sea biblioteca reutilizable: en otro ejercicio los id del HTML cambian (frase, texto, nombre…) pero la lógica de invertir palabras sigue igual. Si buscaras id="frase" dentro de miFuncion, tendrías que modificar la función en cada proyecto. Los enlaces con el HTML son responsabilidad de la capa app (variables + main).
▶ 6. ¿Cuál es la entrada y la salida de leerTexto?
Entrada: un elemento DOM de tipo input (referencia guardada en una variable). Salida: string con lo que escribió el usuario, sin espacios al inicio ni al final (trim). No usa return para mostrar en pantalla; devuelve datos para que otra función los use.
▶ 7. ¿Por qué mostrarTexto no tiene return útil?
Porque su efecto es visual: escribe en el HTML con elemento.textContent = texto. La "salida" la ve el usuario en pantalla, no otro cálculo en JavaScript. En la guía del curso eso se describe como «salida: ninguna» (efecto secundario en el DOM).
▶ 8. ¿Qué hace funcionMain paso a paso (pizarra)?
1. Lee con leerTexto(input).
2. Validación JS: si el texto está vacío, muestra "Escribe una frase" y termina con return.
3. Llama a la función pertinente: miFuncion(texto).
4. Recibe el string resultado.
5. Escribe en HTML con mostrarTexto(elementoResultado, resultado).
▶ 9. ¿Qué evento escuchamos y en qué elemento?
Evento: "click" (clic del ratón o equivalente en táctil). Elemento: btnInvertir (botón con id="btnCalcular" en el HTML). El callback es una función flecha que llama funcionMain(inputFrase, parrafoResultado). No usamos submit porque no hay formulario; el botón es type="button".
▶ 10. ¿Por qué el <script> está al final del body?
Porque al ejecutarse getElementById("frase") los elementos deben existir ya en el DOM. Si el script estuviera en el head sin esperar, inputFrase podría ser null y el botón no funcionaría. Al final del body, input, botón y párrafo resultado ya están creados.
▶ 11. ¿Qué relación hay entre for="frase" en el label y id="frase" en el input?
Deben coincidir para accesibilidad: al hacer clic en «Escribe una frase» el foco va al input correcto. En JavaScript usas el mismo identificador con getElementById("frase"). Es el mismo id para HTML semántico y para enlazar con JS.
▶ 12. Nombra las tres partes del archivo app.js según la guía del curso.
1. Declaración de variables — enlaces con getElementById.
2. Declaración de funciones — biblioteca + ayudantes + funcionMain.
3. Ejecución de código — addEventListener que dispara el main. Ese orden separa «página» de «lógica reutilizable».
▶ 13. ¿Se pueden reutilizar TODAS las funciones sin cambiar nada?
No. Solo la biblioteca (miFuncion, invertirPalabra) se copia sin modificar el interior. leerTexto y mostrarTexto se copian igual pero las llamas con otros elementos en otra página. funcionMain en otro ejercicio suele cambiar la función que llamas (por ejemplo cuentaCaracteres en vez de miFuncion). Eso es diseño correcto, no un error.
▶ 14. ¿Qué pasa si el usuario pulsa Invertir con el input vacío?
leerTexto devuelve "" después del trim. La condición texto === "" es verdadera. Se ejecuta mostrarTexto(elementoResultado, "Escribe una frase") y return evita llamar a miFuncion. Es validación en la capa app, no en la biblioteca.
▶ 15. ¿Por qué usamos textContent y no innerHTML en mostrarTexto?
textContent trata todo como texto plano: si el usuario escribiera caracteres raros o etiquetas, no se interpretan como HTML. innerHTML podría ejecutar o renderizar código HTML y es menos seguro para datos del usuario. Para mostrar el resultado de invertir palabras, textContent es la opción adecuada.
