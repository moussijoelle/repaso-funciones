Guide de l'exercice

Compter les voyelles et les consonnes dans une chaîne de texte

Bonjour ! Cette page explique l'exercice comme en cours, sans jargon compliqué.

De quoi parle l'exercice ?

On te demande de créer une petite machine automatique (en programmation, on l'appelle une fonction). Tu lui donnes une phrase — par exemple « Hola Mundo » — et elle te répond combien il y a de voyelles et de consonnes dans cette phrase.

Exemple attendu : miFuncion("Hola Mundo") → Vocales: 4, Consonantes: 5

Les mots importants (version simple)

Une chaîne de texte
C'est juste une suite de lettres (et parfois d'espaces). Exemple : "Hola Mundo" — les guillemets montrent que c'est du texte pour l'ordinateur.
Une fonction
C'est comme une recette avec un nom. Tu lui donnes un ingrédient (ici : la phrase), elle fait le travail et te donne un résultat.
Voyelles
En espagnol (comme dans l'exemple), ce sont en général : a, e, i, o, u (majuscules ou minuscules : A, E, I, O, U).
Consonnes
Toutes les lettres qui ne sont pas des voyelles : H, l, M, n, d, etc.
Espaces
Dans "Hola Mundo", l'espace entre Hola et Mundo n'est ni une voyelle ni une consonne — on ne le compte généralement pas.

L'exemple qu'on te donne

  • Voyelles : o, a, u, o → 4
  • Consonnes : H, l, M, n, d → 5

Donc ta fonction doit afficher (ou renvoyer) quelque chose comme : Vocales: 4, Consonantes: 5

Ce que tu dois faire, concrètement

  1. Recevoir la phrase (par exemple "Hola Mundo").
  2. Parcourir chaque caractère un par un (comme lire la phrase lettre par lettre).
  3. Pour chaque caractère :
    • si c'est une lettre et une voyelle → +1 aux voyelles ;
    • si c'est une lettre et une consonne → +1 aux consonnes ;
    • si ce n'est pas une lettre (espace, chiffre, signe…) → souvent on ne compte pas.
  4. Montrer le résultat final : combien de voyelles et combien de consonnes.

Pourquoi c'est un bon exercice ?

Tu t'entraînes à :

  • utiliser une fonction avec un paramètre (la phrase) ;
  • faire une boucle (répéter une action pour chaque lettre) ;
  • faire des conditions (« si c'est une voyelle… sinon si c'est une consonne… ») ;
  • travailler avec du texte en programmation.

Qu'est-ce qu'importer un module ?

Imagine que ton programme est un grand cahier divisé en petits carnets :

  • Un carnet contient les fonctions pour compter les voyelles.
  • Un autre contient des fonctions pour une autre page.
  • Le fichier principal ne copie pas tout : il dit seulement « apporte-moi ça du carnet 2 ».

C'est importer un module : utiliser du code qui est dans un autre fichier, sans tout coller au même endroit.

Dans ton exercice actuel, tu as un seul fichier app.js relié au HTML — tu n'as pas besoin d'importer de module. Le bloc « importation de modules » reste vide, et c'est normal.

Ta bibliothèque de fonctions

Voici l'organisation que tu vises — et c'est la bonne :

  • esVocal → dit seulement si une lettre est une voyelle
  • esLetra → dit seulement si c'est une lettre
  • contarVocales → compte les voyelles dans un texte
  • contarConsonantes → compte les consonnes dans un texte
  • formatearResultado → fabrique le message « Vocales: X, Consonantes: Y »
  • funcionMain → seule à lire l'input et écrire dans #resultado

C'est une bibliothèque : des fonctions indépendantes (elles ne touchent pas au DOM ; elles reçoivent des données et renvoient quelque chose).

funcionMain est le directeur : il appelle la bibliothèque et fait le lien entre le HTML et la logique.

Comment savoir si une fonction est « de bibliothèque » ?

Pose-toi ces questions :

  1. A-t-elle une entrée claire ? (texte, lettre, nombres…)
  2. A-t-elle une sortie claire ? (return avec un nombre, un booléen ou une chaîne)
  3. N'utilise-t-elle pas document, getElementById, ni innerHTML ?
  • Si les trois réponses sont oui → fonction de bibliothèque.
  • Si elle touche le DOM → seulement funcionMain (ou très peu de fonctions « de page »).

Cómo decidir qué funciones necesitas (método)

Resumen del flujo

Usuario → submit → funcionMain
                        ↓
            lee inputTexto.value
                        ↓
      contarVocales / contarConsonantes
                        ↓
            formatearResultado
                        ↓
  zonaResultado.textContent = mensaje

Método humano para descubrir las funciones

  1. Escribe el flujo en pasos (entrada → proceso → salida).
    Entrada: texto del input (cadena). Proceso: contar vocales y consonantes. Salida: mostrar Vocales: X, Consonantes: Y.
  2. Cada bloque que sea una tarea sola suele ser una función.
    Ejemplos: “decidir si una letra es vocal”, “contar vocales”, “construir el texto final”, “leer input y escribir en pantalla”.
  3. Si hay condiciones repetidas, sepáralas.
    En este ejercicio se repiten: “¿es letra?” y “¿es vocal?” → salen esLetra y esVocal.
  4. Separa lógica de DOM.
    Biblioteca (sin DOM): contar/formatear. Una sola función toca la página: funcionMain.
  5. Truco práctico: empieza con todo en funcionMain y luego extrae funciones pequeñas.
    Cada vez que una parte se repite o crece, la sacas a una función con entrada y salida claras.

Aplicado a este ejercicio

  • esVocal(letra): regla clara “vocal sí/no”.
  • esLetra(caracter): para no contar espacios/símbolos.
  • contarVocales(cadena): objetivo único: contar vocales.
  • contarConsonantes(cadena): objetivo único: contar consonantes.
  • formatearResultado(vocales, consonantes): construir el texto final.
  • funcionMain(event): leer el input y escribir en #resultado.

Entonces… ¿una función es una tarea?

Sí: una función suele ser una tarea con entrada, proceso y salida. La buena tarea es la que está bien definida y no intenta hacer muchas cosas a la vez.

Explication “comme une prof” (autre façon)

L'idée principale

Une fonction, c'est comme un mini-exercice à l'intérieur de l'exercice : une petite chose claire que tu peux répéter et réutiliser.

Comparaison 1 : la cuisine

Imagine que tu cuisines « pâtes avec sauce ».

  • Le plat complet = ton programme / ta page.
  • Une fonction = une étape de la recette.

Exemples :

  • esVocal(letra) = « est-ce une voyelle ? » → répond oui/non.
  • contarVocales(texto) = « combien de voyelles ? » → répond un nombre.
  • formatearResultado(...) = « présenter le résultat » → répond un texte.
  • funcionMain() = « la personne qui cuisine » : elle lit l'input et écrit sur la page.

Comparaison 2 : une petite usine

Pense à une usine : entrée (ce que tu donnes) → machine (la fonction) → sortie (ce qu'elle renvoie).

Exemple : entrée \"Hola Mundo\" → machine contarVocales → sortie 4.

Règle d'or (bibliothèque vs page)

Si une fonction n'a pas besoin de document / getElementById et fonctionne sans HTML, alors c'est une fonction de bibliothèque. Si elle lit/écrit sur la page, c'est plutôt la fonction principale (funcionMain).

Une image mentale

Imagine que tu lis la phrase à voix haute, lettre par lettre, avec deux boîtes devant toi : une pour les voyelles, une pour les consonnes. À chaque lettre, tu mets un caillou dans la bonne boîte. À la fin, tu comptes les cailloux dans chaque boîte.
