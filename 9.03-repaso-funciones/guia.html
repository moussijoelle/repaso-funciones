1. Enunciado y consigna

Ejercicio: Programa una función que, dada una String, te devuelva un Array de textos separados por cierto carácter.

miFuncion('hola que tal', ' ')
// devuelve → ['hola', 'que', 'tal']

Qué pide el profe (obligatorio)

  • Crear tu propia función (no basta con usar split suelto sin declarar nada).
  • Dos entradas: el texto y el separador.
  • Una salida: un array de strings.
  • Que el ejemplo con espacio funcione exactamente como arriba.

Qué NO pide el enunciado

  • No exige HTML ni formulario.
  • No exige un input para el separador en la página.
  • El espacio ' ' del ejemplo es un valor de prueba, no significa que la función solo sirva con espacios.

Por qué no ves la coma ni el guion en el resultado

El separador actúa como tijera: corta el texto pero no forma parte de los trozos del array. Si en pantalla ves comas entre palabras, vienen de join(', ') al mostrar el resultado, no del separador original.

Entrada: 'hola que tal' + ' ' Corte: hola | que | tal (el espacio desaparece) Salida: ['hola', 'que', 'tal']

7. Funciones de biblioteca — explicación y dónde usarlas

¿Qué es una función de biblioteca?

Una función tuya que:

  • Hace una sola cosa: entradas → salida con return.
  • No conoce el HTML (sin getElementById).
  • La puedes copiar a funciones.js y reutilizar en otros ejercicios sin cambiar su código.
  • Puede usar funciones del lenguaje (split, slice…) dentro; lo importante es que tú declaras la función con nombre.

Tu función de biblioteca en este ejercicio

const dividirTexto = (texto, separador) => {
    return texto.split(separador);
};
PreguntaRespuesta

¿En qué tipo de página puedes usar dividirTexto?

Tipo de página / casoEjemplo de uso
Formulario de búsqueda por palabras Dividir la búsqueda en términos: dividirTexto(busqueda, ' ')
Lista de etiquetas (tags) Usuario escribe "html,css,js" → dividirTexto(etiquetas, ',')
Importar datos CSV simples Una línea "Ana;25;Madrid" → dividirTexto(linea, ';')
Rutas o slugs de URL "blog/2024/articulo" → dividirTexto(ruta, '/')
Separar nombre completo "María García López" → dividirTexto(nombre, ' ')
Procesar respuestas de un textarea Varias líneas separadas por salto de línea → dividirTexto(texto, '\n')
Calculadora o app de texto (como la tuya) Frase del input → dividirTexto(frase, ' ') y mostrar palabras
Cualquier ejercicio del curso Copias funciones.js entero; en el nuevo app.js solo cambias ids y cómo muestras el resultado

La biblioteca no sabe si el dato viene de un input, de un archivo o de una API. Solo recibe strings y devuelve arrays. Por eso sirve en casi cualquier página que necesite trocear texto.

8. Cómo probar que funciona

  1. Abre index.html en el navegador.
  2. Escribe hola que tal en el input.
  3. Pulsa Dividir.
  4. Debes ver: hola, que, tal en la zona de resultado.
  5. Abre consola (F12) y escribe: dividirTexto('hola que tal', ' ') → debe devolver el array con tres elementos.
  6. Si hay error en rojo, revisa que los id del HTML coincidan con getElementById.

9. Test — 15 preguntas

Haz el test sin abrir las respuestas. Clic en cada pregunta para ver la explicación detallada.

1. ¿Qué devuelve dividirTexto('hola que tal', ' ')?

Devuelve el array ['hola', 'que', 'tal'].

La función recibe la frase completa como primer argumento y el espacio como segundo. Internamente split(' ') corta en cada espacio. Cada palabra pasa a ser un elemento del array. El separador (espacio) no aparece dentro de los elementos porque split lo usa solo para marcar los cortes.

2. ¿Cuál es la función de biblioteca y cuál es el main?

Biblioteca: dividirTexto — solo transforma datos (texto + separador → array).

Main: funcionMain — lee el formulario, llama a dividirTexto y escribe en #resultado.

addEventListener no es ni biblioteca ni main; es la línea que conecta el submit del formulario con funcionMain.

3. ¿Por qué usamos evento.preventDefault()?

Por defecto, al enviar un formulario el navegador recarga la página y pierdes el estado de JavaScript.

preventDefault() cancela ese comportamiento por defecto. Así la página no se recarga, puedes leer los inputs, procesar con tu función y mostrar el resultado en el mismo sitio.

4. ¿Por qué el separador no aparece en el array resultado?

Porque split usa el separador como punto de corte, no como contenido a guardar.

Ejemplo: 'a,b,c'.split(',') → ['a','b','c']. Las comas desaparecen del resultado. Lo mismo con espacios o guiones. Es el comportamiento estándar del método y coincide con lo que pide el enunciado del ejercicio.

5. ¿Qué hace partes.join(', ') y por qué no es lo mismo que split?

join(', ') hace lo contrario de split para mostrar: une los elementos del array en un único string, poniendo coma y espacio entre ellos.

['hola','que','tal'].join(', ') → 'hola, que, tal'.

Las comas que ves en pantalla las añade join solo para que sea legible. No son el separador original del ejercicio. split parte; join une.

6. ¿Hace falta un input para el separador según el enunciado?

No. El enunciado solo pide programar la función con dos parámetros.

El ejemplo usa espacio: miFuncion('hola que tal', ' '). En la web puedes pasar ' ' fijo en código dentro de funcionMain, como hace tu proyecto actual. Un input separador sería extra para que la usuaria elija otro carácter, pero no es obligatorio para cumplir el ejercicio.

7. ¿Se puede reutilizar dividirTexto en otro ejercicio sin cambiarla?

Sí. Esa es la definición de función de biblioteca.

Copias la función (o el archivo funciones.js) al nuevo proyecto. En el nuevo app.js cambias los ids del HTML, cómo lees los datos y cómo muestras el resultado. El código de dividirTexto permanece idéntico; solo cambian los argumentos que le pasas al llamarla.

8. ¿Por qué getElementById va en variables y no dentro de dividirTexto?

Porque getElementById enlaza JavaScript con esta página concreta y sus ids.

Si metieras DOM dentro de dividirTexto, ya no sería reutilizable: en otro HTML los ids podrían ser distintos. La biblioteca debe recibir datos puros (strings) por parámetro, no buscarlos en la página.

9. ¿Qué es inputTexto.value?

inputTexto es la referencia al elemento HTML con id="texto".

.value es la propiedad que contiene el texto que la usuaria escribió en ese momento. Es un string. Ese string es lo que pasas como primer argumento a dividirTexto.

10. ¿Qué devuelve dividirTexto('hola', ' ')?

Devuelve ['hola'] — un array con un solo elemento.

No hay espacios en "hola", así que no hay cortes. split devuelve el texto entero como único trozo. Sigue siendo un array válido, solo que con longitud 1.

11. ¿Cuál es la diferencia entre split y tu función dividirTexto?

split es un método del lenguaje JavaScript, integrado en los strings.

dividirTexto es tu función: una capa con nombre claro que encapsula la lógica del ejercicio. Puedes añadir validaciones, cambiar la implementación más adelante o exportarla como biblioteca, y el resto del código sigue llamando dividirTexto igual.

El profe pide funciones tuyas genéricas y reutilizables, no solo usar métodos sueltos sin declarar nada.

12. ¿Por qué el <script> está al final del body?

Porque getElementById necesita que los elementos HTML ya existan en el DOM cuando se ejecuta el script.

Si cargaras app.js en el <head> sin defer, el formulario y los inputs aún no existirían y getElementById devolvería null, causando errores al usar el listener o leer .value.

13. ¿Qué hace exactamente addEventListener('submit', funcionMain)?

Registra un escuchador en el formulario: cuando ocurre el evento submit (usuario pulsa Enter o el botón Dividir), el navegador ejecuta la función funcionMain.

No ejecuta funcionMain inmediatamente al cargar la página — solo cuando se envía el formulario. Por eso va en la sección EJECUCIÓN DE CÓDIGO y debe ser una línea que delega en main, no todo el código metido dentro del listener.

14. ¿Qué entradas y salidas tiene funcionMain?

Entrada: el parámetro evento (objeto del evento submit).

También lee indirectamente la frase desde inputTexto.value — eso no es un parámetro de la función, sino lectura del DOM.

Salida: no usa return con un valor útil. La "salida" es visual: modifica el DOM escribiendo en zonaResultado.textContent. Las funciones main suelen actuar sobre la página; las de biblioteca devuelven datos con return.

15. Si copias dividirTexto a una app de etiquetas con comas, ¿cómo la llamarías?

Sin cambiar la función, llamarías por ejemplo:

const etiquetas = dividirTexto('html,css,javascript', ',');

Resultado: ['html', 'css', 'javascript'].

En el main de esa app leerías un input de etiquetas, pasarías coma como segundo argumento, y mostrarías cada tag en la interfaz. La biblioteca sigue siendo la misma; solo cambian los datos de entrada y la presentación en pantalla.
