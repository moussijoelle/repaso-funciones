Guía del ejercicio: repetir un texto X veces

Abrir la aplicación · Objetivo: miFuncion('Hola Mundo', 3) → Hola Mundo Hola Mundo Hola Mundo

HTML línea a línea JS línea a línea Biblioteca Test (15 preguntas)

Enunciado

Programa una función que repita un texto X veces. Ejemplo: miFuncion('Hola Mundo', 3) devuelve la frase tres veces separada por espacios.

Estructura del profe: variables → funciones → ejecución (addEventListener).

Funciones biblioteca — qué son y cómo reutilizarlas

Biblioteca = funciones con entradas y salidas claras, sin getElementById dentro. Las copias a funciones.js y no las modificas en el siguiente ejercicio.

miFuncion(texto, veces)

Entrada: frase (string) + número de repeticiones.

Salida: string con la frase repetida y espacios.

Reutilizar: en consola o en cualquier ejercicio — miFuncion('Adiós', 2) sin cambiar el código.

leerTexto(input)

Entrada: cualquier <input type="text">.

Salida: lo que escribió el usuario.

Reutilizar: pasa otro input — leerTexto(document.getElementById('nombre')).

leerNumero(input)

Entrada: input numérico.

Salida: número (no string).

Reutilizar: edad, cantidad, precio… mismo código, otro id en el HTML.

mostrarTexto(elemento, texto)

Entrada: div/párrafo + string.

Salida: ninguna (efecto visual).

Reutilizar: cualquier zona de resultado de cualquier página.

funcionMain(evento, inputTexto, inputVeces, elementoResultado)

Entrada: evento submit + 3 elementos del DOM.

Salida: ninguna; organiza las otras funciones.

Reutilizar: en otra página cambias solo qué elementos pasas en el addEventListener.

Separar en funciones.js (sin módulos)

<!-- index.html -->
<script src="js/funciones.js"></script>
<script src="js/app.js"></script>
  • funciones.js → las 5 funciones (líneas 9-31 de tu app actual).
  • app.js → solo variables + addEventListener.
  • Orden: primero biblioteca, después app.

Flujo de datos

Usuario → submit → funcionMain
  → leerTexto / leerNumero
  → miFuncion
  → mostrarTexto → pantalla

Test — 15 preguntas

Haz clic en cada pregunta para ver la respuesta. Intenta responder antes de abrir.

▶ 1. ¿Qué debe devolver miFuncion('Hola Mundo', 3)?

Debe devolver exactamente un string: Hola Mundo Hola Mundo Hola Mundo — la frase tres veces con un espacio entre cada repetición. No debe llevar comas ni saltos de línea extra. El orden importa: siempre texto + espacio + texto…

▶ 2. ¿Para qué sirve Array(veces).fill(texto).join(' ')?

Array(veces) crea un array vacío de longitud veces. .fill(texto) lo rellena con copias del mismo string. .join(' ') une todas las copias en un solo string separado por espacios. Es la forma de repetir sin escribir un bucle for a mano (usa funciones del lenguaje).

▶ 3. ¿Qué diferencia hay entre parámetro y argumento?

El parámetro es el nombre en la declaración: (texto, veces). El argumento es el valor real al llamar: miFuncion('Hola', 3). En tu app, texto y veces vienen de leerTexto y leerNumero después de que el usuario rellena el formulario.

▶ 4. ¿Por qué usamos getElementById solo en variables y no dentro de miFuncion?

Porque miFuncion debe ser biblioteca: reutilizable en cualquier página sin cambiar su código. Si buscara id="texto" dentro, en otro ejercicio con otro id habría que modificar la función. Los id son cosa de app.js (esta aplicación); la lógica de repetir solo necesita strings y números.

▶ 5. ¿Qué hace evento.preventDefault() en funcionMain?

El formulario, al enviarse, intenta recargar la página (comportamiento por defecto del navegador). preventDefault() cancela esa recarga para que tu JavaScript pueda leer los inputs y mostrar el resultado en el mismo sitio, sin perder lo escrito ni parpadear la página.

▶ 6. ¿Por qué leerNumero usa Number() y no devuelve input.value directamente?

Porque input.value siempre es un string (texto), aunque el input sea type="number". Array(veces) y la repetición necesitan un número real. Number('3') → 3 (tipo number). Sin conversión, podrías tener errores raros al crear el array.

▶ 7. ¿Cuál es la diferencia entre textContent e innerHTML en mostrarTexto?

textContent trata todo como texto plano: si el usuario escribe <script>, se muestra como caracteres, no se ejecuta. innerHTML interpretaría etiquetas HTML y podría ser inseguro. Para este ejercicio, textContent es la opción correcta y más segura.

▶ 8. ¿Qué evento escuchamos y en qué elemento?

Evento: 'submit' (enviar formulario). Elemento: formulario (el que tiene id="formRepetir"). Se dispara al pulsar el botón «Repetir texto» o al pulsar Enter en un campo del form. El callback recibe el objeto evento y lo pasa a funcionMain.

▶ 9. ¿Qué pasa si veces es 0 o negativo?

Con Array(0) obtienes un array vacío y join devuelve '' (string vacío). Con valores negativos el comportamiento de Array no es útil para repetir. El HTML limita con min="1", pero en biblioteca estricta podrías validar en funcionMain antes de llamar miFuncion.

▶ 10. Nombra las tres partes del archivo según tu guía de curso.

1. Declaración de variables — getElementById / enlaces con el HTML.
2. Declaración de funciones — biblioteca + funcionMain.
3. Ejecución de código — addEventListener que llama a funcionMain. Ese orden ayuda a leer el archivo y a separar «qué es la página» de «qué es reutilizable».

▶ 11. ¿Por qué el <script> está al final del body?

Porque getElementById('texto') necesita que el HTML ya exista en el DOM. Si el script estuviera en el head sin esperar, los elementos podrían ser null y fallaría. Al final del body, formulario, inputs y #resultado ya están creados.

▶ 12. ¿Qué relación hay entre for="texto" en el label y id="texto" en el input?

El atributo for del <label> debe coincidir con el id del input. Así, al hacer clic en la palabra «Texto», el cursor va al campo correcto (accesibilidad y usabilidad). En JavaScript usas el mismo id con getElementById('texto') — tres usos del mismo identificador, mismo propósito de enlace.

▶ 13. ¿Cuáles son funciones del lenguaje (no personalizadas) en este ejercicio?

Por ejemplo: Array, fill, join, Number, document.getElementById, addEventListener, preventDefault. No las inventas; JavaScript o el navegador ya las traen. Tú inventas (personalizas): miFuncion, leerTexto, leerNumero, mostrarTexto, funcionMain.

▶ 14. ¿Cómo reutilizarías la biblioteca en un ejercicio nuevo sin editar las funciones?

Copia funciones.js al nuevo proyecto. En el nuevo app.js solo cambias: los getElementById (si los id cambian) y la línea del listener para pasar los elementos correctos a funcionMain. Ejemplo: funcionMain(evento, inputNombre, inputEdad, divSalida) — las funciones internas siguen iguales.

▶ 15. ¿Por qué funcionMain recibe los inputs como parámetros y no usa las variables globales directamente?

Para que sea una función de biblioteca reutilizable: todo lo que necesita entra por parámetros. En otra página puedes llamar funcionMain(e, otroInput, otroNumero, otroDiv) sin cambiar el cuerpo de funcionMain. Las variables globales de app.js solo sirven para pasar esos argumentos en el addEventListener de esta página concreta.
