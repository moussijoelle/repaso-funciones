Guía del ejercicio 9.20 — Quitar duplicados

← Volver a la página del ejercicio

1. En qué consiste el ejercicio

Debes programar una función que reciba un arreglo (array) y devuelva otro arreglo sin duplicados, manteniendo el orden y solo la primera aparición de cada valor.

miFuncion(["x", 10, "x", 2, "10", 10, true, true])
// → ["x", 10, 2, "10", true]

Palabras clave

TérminoSignificado simple
FunciónRecibe datos por parámetro y devuelve un resultado con return.
Arreglo / arrayLista ordenada de valores: [a, b, c].
DuplicadoEl mismo valor repetido más adelante en la lista.
DevolverEn código significa return, no “mostrar en pantalla”.

Trampa importante: tipos distintos

En JavaScript, 10 (número) y "10" (texto) no son iguales. Por eso ambos se quedan en el resultado. La comparación usa === (igualdad estricta).

Lógica de la página (main + biblioteca)

  1. funcionPrincipal (única que toca el DOM): lee el input, valida, llama a las funciones puras y muestra el mensaje.
  2. miFuncion y el resto: una tarea cada una; entran y salen por parámetro y return.
  3. Orden del archivo JS: variables → funciones → addEventListener.
Flujo: Usuario envía el formulario → principal lee texto → entradaValida → textoAValor → miFuncion → mensajeResultado → se escribe en #resultado.

Resumen en francés (idea del ejercicio)

Tu dois écrire une fonction qui nettoie une liste : la première fois qu’un élément apparaît, on le garde ; s’il revient après, on l’ignore. L’ordre ne change pas.

6. Test — 15 preguntas (pulsa para ver la respuesta)

Las respuestas están ocultas en <details>. Intenta responder antes de abrirlas.

1. ¿Qué debe devolver miFuncion con ["a", "a", "b"]?

Debe devolver ["a", "b"]. Solo se conserva la primera "a"; la segunda se ignora porque ya estaba en el resultado. El orden se mantiene: primero "a", luego "b".

2. ¿Por qué 10 y "10" pueden coexistir en el resultado?

Porque son tipos distintos: 10 es número y "10" es string. JavaScript los compara con ===, que exige mismo valor y mismo tipo. No se consideran duplicados.

3. ¿Qué significa “devolver” en el enunciado del ejercicio?

Significa usar return dentro de la función para entregar el resultado a quien la llamó. No significa mostrar en pantalla; mostrar es tarea de funcionPrincipal con el DOM.

4. ¿Qué función es la única que puede tocar el DOM en este proyecto?

funcionPrincipal. Es la que lee inputArray.value y escribe en zonaResultado.textContent. El resto solo trabaja con parámetros y return, por eso pueden guardarse en tu biblioteca de funciones.

5. ¿Para qué sirve evento.preventDefault() en funcionPrincipal?

Cancela el comportamiento por defecto del formulario al enviar (recargar la página). Así la página se queda igual y solo actualizas el div de resultado con JavaScript.

6. ¿Qué hace JSON.parse en textoAValor?

Convierte un string con formato JSON (por ejemplo '["x", 10, true]') en un valor de JavaScript real: aquí, un array con string, número y boolean. Si el texto no es JSON válido, lanza error y entradaValida lo captura.

7. ¿Por qué entradaValida usa try y catch?

Porque JSON.parse falla si la usuaria escribe mal las comillas, olvida corchetes o pone texto suelto. El catch evita que el programa se rompa: en ese caso valido queda false y se muestra el mensaje de error.

8. ¿Qué comprueba la función esArray?

Comprueba que el valor parseado sea un arreglo con Array.isArray(valor). Así rechazas entradas como 42 o "hola" aunque sean JSON válido, porque el ejercicio pide un array.

9. ¿Cómo sabe miFuncion si un elemento ya apareció antes?

Usa yaEstaEnLista, que llama a lista.includes(elemento). Recorre el array original y solo hace push cuando includes devuelve false, es decir, es la primera vez que ve ese valor (con igualdad estricta).

10. ¿Por qué los id del HTML deben coincidir con getElementById?

getElementById("formArray") busca en el documento un elemento cuyo atributo id sea exactamente ese texto. Si el HTML dice id="formTexto" y el JS busca formArray, obtienes null y el programa falla al hacer addEventListener.

11. ¿Qué evento escucha addEventListener y cuándo se dispara?

Escucha "submit" en el formulario. Se dispara cuando la usuaria pulsa el botón de enviar o pulsa Enter en un campo del form. Entonces se ejecuta funcionPrincipal.

12. ¿Cuál es la diferencia entre textContent e innerHTML para el resultado?

textContent trata todo como texto plano; no interpreta etiquetas HTML. Es más seguro para mostrar el array o un mensaje de error. innerHTML interpretaría tags y podría ser un riesgo si algún día mostraras texto no confiable.

13. Si el usuario escribe [1, 2, 2, 3], ¿qué guarda la variable resultado en funcionPrincipal?

Guarda [1, 2, 3]. miFuncion devuelve ese array; la principal no lo muestra crudo: pasa por mensajeResultado y arrayATexto, que lo convierten a string con JSON.stringify para el div.

14. ¿Por qué todas las funciones de biblioteca son flecha (=>)?

Es la convención de tu curso y tu biblioteca: funciones constantes reutilizables, sintaxis corta y clara. Siguen siendo funciones normales con parámetros y return; solo cambia la forma de escribirlas respecto a function nombre() {}.

15. Ordena estos pasos de la funcionPrincipal: mostrar, validar, leer input, llamar miFuncion.

Orden correcto: (1) leer input con inputArray.value, (2) validar con entradaValida, (3) si es válido parsear y llamar miFuncion(valores) guardando el return en resultado, (4) preparar mensaje con mensajeResultado, (5) mostrar con zonaResultado.textContent = mensaje. La validación va antes de confiar en el parseo para el cálculo.
