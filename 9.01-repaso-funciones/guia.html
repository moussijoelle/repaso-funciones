Guía del ejercicio: validar formulario y contar caracteres

Objetivo: que tus ejercicios siempre sigan el mismo patrón y puedas reutilizar tus funciones en una biblioteca.

1) Regla de oro (la idea de la profe)

  • Biblioteca (funciones puras / independientes): no usan document, no leen inputs, no escriben en HTML. Solo reciben valores y devuelven resultados con return.
  • Main/handler (DOM): es lo único que toca el HTML. Lee el formulario, llama a funciones de la biblioteca y pinta el resultado.
  • Un solo return: en cada función, crea un objeto respuesta, modifícalo en el if y devuélvelo al final. Evita varios return dentro de la misma función.
  • Comentarios a la derecha: en cada línea de código, un comentario corto al final explicando qué hace esa línea.

¿Qué es exactamente una función independiente (o “de biblioteca”)?

Una función independiente es una función que puedes reutilizar en cualquier ejercicio porque:

  • Recibe los datos por parámetros (no los busca en la página).
  • Devuelve un resultado con return (no escribe en el HTML).
  • No depende del DOM: no usa document, getElementById, querySelector, addEventListener, innerHTML, etc.
  • Hace una sola cosa (ej: validar, normalizar, contar, calcular).

Ejemplos (funciones flecha independientes):

const normalizarTexto = (valor) => String(valor ?? "").trim();

const contarCaracteres = (texto) => normalizarTexto(texto).length;

const validarTextoObligatorio = (texto) => {
  const limpio = normalizarTexto(texto);
  const respuesta = { ok: true, mensaje: "" };

  if (limpio.length === 0) {
    respuesta.ok = false;
    respuesta.mensaje = "Escribe un texto.";
  }
  return respuesta;
};

Mal (varios return): if (...) return { ok: false, ... }; return { ok: true, ... };
Bien (un solo return): creas respuesta, la cambias en el if y al final return respuesta;.

No es biblioteca (esto depende de la página):

const input = document.getElementById("texto");
input.addEventListener("input", () => {
  // ...
});

Frase para clase: “Separé la lógica en funciones independientes que reciben datos y devuelven resultados; y dejé en el handler la parte de leer el formulario y mostrar el resultado.”

2) Mapa mental (siempre el mismo)

  • Entrada: leer value desde el formulario.
  • Normalizar: convertir al tipo correcto y limpiar (por ejemplo trim()).
  • Validar: devolver un objeto como { ok, mensaje }.
  • Calcular: devolver el resultado (número, string, boolean...).
  • Salida: escribir en #resultado.

3) Estructura recomendada de archivos

tu-ejercicio/
  index.html
  js/
    lib.js   (funciones independientes)
    app.js   (escuchadores + main)

En esta carpeta todavía no existe js/; la puedes crear cuando empieces a aplicar el patrón.

4) Plantilla de HTML (formulario + resultado)

<form id="form">
  <label for="entrada">Escribe algo</label>
  <input id="entrada" name="entrada" type="text" required />

  <button type="submit">Enviar</button>

  <div id="resultado"></div>
</form>

<script src="js/app.js"></script>

5) Plantilla de js/lib.js (funciones flecha independientes)

Estas funciones son ejemplos “base”. Puedes ampliarlas según el ejercicio (primo, factorial, contar vocales, etc.). 

// Normaliza texto: convierte a string y recorta espacios
export const normalizarTexto = (valor) => String(valor ?? "").trim();

export const contarCaracteres = (texto) => normalizarTexto(texto).length;

export const parsearEntero = (valor) => Number.parseInt(String(valor), 10);

export const esNumeroValido = (numero) => Number.isFinite(numero);

export const validarRango = (numero, min, max) => {
  if (!Number.isFinite(numero)) return { ok: false, mensaje: "No es un número válido." };
  if (numero < min) return { ok: false, mensaje: `Debe ser ≥ ${min}.` };
  if (numero > max) return { ok: false, mensaje: `Debe ser ≤ ${max}.` };
  return { ok: true, mensaje: "" };
};

6) Plantilla de js/app.js (escuchador + “main”)

import { normalizarTexto, contarCaracteres } from "./lib.js";

const form = document.querySelector("#form");
const entrada = document.querySelector("#entrada");
const resultado = document.querySelector("#resultado");

form.addEventListener("submit", (event) => {
  event.preventDefault();

  const texto = normalizarTexto(entrada.value);

  if (texto.length === 0) {
    resultado.textContent = "Escribe un texto.";
    return;
  }

  const cantidad = contarCaracteres(texto);
  resultado.textContent = `Caracteres: ${cantidad}`;
});

Nota: si usas import en app.js, el script en HTML debe ser <script type="module" src="js/app.js"></script>.

8) Este ejercicio (resumen para explicar en clase)

  • Qué pide: validar la entrada de un formulario y contar caracteres de una cadena (ej: "Hola mundo" → 10).
  • Qué hace tu programa: el usuario escribe una frase, envía el formulario, el JS valida y muestra “Caracteres: X”.
  • Cómo lo organizaste: funciones independientes (lógica) + una función principal con DOM (conecta el formulario con la lógica).

Cómo decirlo rápido: “Tengo funciones independientes para normalizar/validar/contar y una función principal que escucha el formulario y pinta el resultado.”

9) Explicación línea por línea: tu index.html (lo importante)

Aquí explico solo las partes que importan para el ejercicio.

  • <form id="formtexto">: identifica el formulario; el JS lo usa para escuchar el submit.
  • <label for="texto">: el for apunta al input con id="texto".
  • <input id="texto" ... required>: donde el usuario escribe la frase; required añade validación HTML básica.
  • <button type="submit">: al pulsar, dispara el evento submit del formulario.
  • <div id="resultado">: zona donde el JS escribe el mensaje final.
  • <script src="js/app.js">: carga tu JavaScript al final para que el HTML ya exista cuando el JS se ejecute.

10) Explicación línea por línea: tu js/app.js

Tu archivo tiene dos partes: lógica independiente (reutilizable) y DOM (conecta con la página).

10.1) Variables DOM (conectar JS con HTML)

  • document.getElementById("formtexto"): busca el formulario por su id. Comentario a la derecha: // Formulario
  • document.getElementById("texto"): busca el input donde escribe el usuario. Comentario: // Campo de texto
  • document.getElementById("resultado"): busca el div donde mostrarás el resultado. Comentario: // Zona del resultado

10.2) Funciones independientes (biblioteca dentro de app.js)

  • normalizarTexto(valor): convierte a texto y hace trim() (sirve para que “solo espacios” cuente como vacío).
  • validarTextoObligatorio(texto): crea respuesta, la modifica si el texto está vacío y devuelve { ok, mensaje } con un solo return.
  • contarCaracteres(texto): devuelve un número con length del texto normalizado.
  • procesarTexto(texto): coordina la lógica con el mismo patrón de respuesta y un solo return.

10.3) Comentarios a la derecha (estilo del curso)

Cada línea ejecutable lleva un comentario corto al final, separado por dos espacios:

const limpio = normalizarTexto(texto);  // Texto preparado
const respuesta = { ok: true, mensaje: "" };  // Respuesta inicial

if (limpio.length === 0) {  // Texto vacío
  respuesta.ok = false;  // Hay error
  respuesta.mensaje = "Escribe un texto.";  // Aviso al usuario
}
return respuesta;  // Resultado validación

10.3) Función principal (DOM) + escuchador

  • vincularFormulario(...): es tu función principal del programa porque deja el formulario “activo”.
  • form.addEventListener("submit", ...): el escuchador. Se ejecuta cuando el usuario envía el formulario.
  • event.preventDefault(): evita que la página se recargue al enviar.
  • output.textContent = ...: escribe el mensaje en el HTML.

11) Mini‑biblioteca: categorías de funciones independientes

  • Normalización: limpian/transforman entrada (ej: normalizarTexto, parsearEntero).
  • Validación: comprueban reglas y devuelven { ok, mensaje } (ej: validarTextoObligatorio, validarRango).
  • Cálculo: devuelven resultados (ej: contarCaracteres, primo/factorial/suma).
  • Orquestación (lógica): combinan varias funciones puras (ej: procesarTexto).

Regla práctica: si una función toca document, eventos o textContent, ya no es biblioteca: es DOM/UI.

11.1) Funciones completas (listas para copiar y reutilizar)

Estas son las funciones completas (sin import/export) para reutilizarlas en otros ejercicios. Puedes copiarlas tal cual a tu app.js o a un futuro lib.js.

Funciones de biblioteca (independientes)

Aquí tienes cada función con su código completo y su explicación justo debajo, para copiar/pegar sin buscar.

normalizarTexto(valor)

const normalizarTexto = (valor) => String(valor ?? "").trim();

Convierte cualquier valor a texto y recorta espacios con trim(). Útil antes de validar o calcular: evita errores con null/undefined y hace que “solo espacios” se considere vacío. Devuelve string.

validarTextoObligatorio(texto)

const validarTextoObligatorio = (texto) => {  // Valida texto obligatorio
  const limpio = normalizarTexto(texto);  // Texto preparado
  const respuesta = { ok: true, mensaje: "" };  // Respuesta inicial

  if (limpio.length === 0) {  // Texto vacío
    respuesta.ok = false;  // Hay error
    respuesta.mensaje = "Escribe un texto.";  // Aviso al usuario
  }
  return respuesta;  // Resultado validación
};

Comprueba si el texto es obligatorio (no vacío, ni solo espacios). Usa un solo return al final con el objeto respuesta.

contarCaracteres(texto)

const contarCaracteres = (texto) => normalizarTexto(texto).length;

Cuenta caracteres del texto normalizado usando .length. Devuelve number. Ejemplo: "Hola mundo" → 10.

procesarTexto(texto)

const procesarTexto = (texto) => {  // Lógica del ejercicio
  const validacion = validarTextoObligatorio(texto);  // Comprueba el texto
  const respuesta = { ok: true, mensaje: "" };  // Respuesta inicial

  if (!validacion.ok) {  // Validación fallida
    respuesta.ok = false;  // Hay error
    respuesta.mensaje = validacion.mensaje;  // Mensaje de error
  } else {  // Texto correcto
    respuesta.mensaje = `Caracteres: ${contarCaracteres(texto)}`;  // Muestra el total
  }
  return respuesta;  // Mensaje final
};

Junta la lógica del ejercicio: valida, calcula el conteo y devuelve el mensaje final con un solo return.

Función principal (DOM/UI)

vincularFormulario({ form, input, output, procesar })

const vincularFormulario = ({ form, input, output, procesar }) => {  // Enlaza DOM y lógica
  form.addEventListener("submit", (event) => {  // Escucha el submit
    event.preventDefault();  // Evita recarga
    output.textContent = procesar(input.value).mensaje;  // Pinta resultado
  });
};

Conecta el formulario con la lógica: escucha el submit, evita recargar la página y escribe el resultado en output. No es biblioteca porque depende del DOM (eventos + textContent).

11.1.3) Ejemplo de uso (conectar HTML con la lógica)

const formtexto = document.getElementById("formtexto");  // Formulario
const inputTexto = document.getElementById("texto");  // Campo de texto
const resultado = document.getElementById("resultado");  // Zona del resultado

vincularFormulario({  // Inicia el programa
  form: formtexto,  // Formulario
  input: inputTexto,  // Input
  output: resultado,  // Salida
  procesar: procesarTexto,  // Función lógica
});

12) Test (15 preguntas) — respuestas ocultas

Úsalo para estudiar: intenta responder sin abrir la solución.

1) ¿Qué significa “validar datos de entrada” en este ejercicio?

Comprobar que el texto que llega desde el formulario cumple reglas (por ejemplo, que no esté vacío ni sean solo espacios) antes de contar caracteres y mostrar el resultado.

2) ¿Por qué usamos trim() al normalizar el texto?

Para eliminar espacios al principio y al final. Así, si el usuario escribe solo espacios, el texto se convierte en "" y se detecta como “vacío”.

3) ¿Qué devuelve una validación “buena práctica”?

Un objeto como { ok: boolean, mensaje: string }, para separar el “resultado” del “mensaje” y poder reutilizar la validación en otros ejercicios.

4) ¿Qué significa que una función sea independiente?

Que recibe datos por parámetros, devuelve un resultado con return y no depende del DOM (no usa document, ni eventos, ni escribe en HTML).

5) ¿Qué pasa si el id del HTML no coincide con getElementById?

getElementById devuelve null. Después, al usar ese valor (por ejemplo null.addEventListener) saldrá un error.

6) ¿Por qué usamos un escuchador submit?

Porque queremos ejecutar el programa cuando el usuario envía el formulario (al pulsar el botón). El escuchador es la forma estándar de reaccionar a esa acción.

7) ¿Para qué sirve event.preventDefault()?

Para evitar que el formulario recargue la página al enviar. Así el resultado se muestra en la misma página sin “reset”.

8) ¿Qué hace contarCaracteres("Hola mundo") y por qué da 10?

Devuelve 10 porque cuenta 4 letras (“Hola”), 1 espacio y 5 letras (“mundo”). Total: 4 + 1 + 5 = 10.

9) ¿Cuál es la función principal de tu programa (la que activa el formulario)?

vincularFormulario, porque es la que registra el escuchador del formulario y conecta la UI con la lógica.

10) ¿Cuál es la ventaja de tener procesarTexto?

Centraliza la lógica: valida y prepara el mensaje final. El DOM solo llama a esa función y muestra el resultado, con menos riesgo de duplicar lógica.

11) ¿Qué parte de tu código “no puede” ser biblioteca?

La parte que usa eventos y modifica el HTML (DOM): addEventListener, textContent, y la búsqueda de elementos con document.

12) ¿Qué diferencia hay entre input.value y el texto normalizado?

input.value es lo que escribió el usuario tal cual; el normalizado es la versión convertida a string y limpiada (por ejemplo sin espacios al inicio/final).

13) ¿Cuándo usarías un escuchador input en vez de submit?

Cuando quieres actualizar el resultado “mientras escribe” sin pulsar botón. En ese caso escuchas el evento input del campo.

14) ¿Cómo comprobarías rápido si el formulario se está encontrando bien?

Con console.log(formtexto). Si imprime el elemento <form ...>, está bien. Si imprime null, el id no coincide.

15) Si quisieras reutilizar tu DOM “en otro ejercicio”, ¿qué harías?

Harías una función como vincularFormulario que recibe { form, input, output, procesar }. Así cambias el HTML y la lógica sin reescribir el “pegamento”.

16) ¿Por qué usar un solo return con respuesta?

Porque es la forma que pide la profe: creas el objeto al inicio, lo modificas en el if y lo devuelves al final. Así la función tiene una sola salida y el código es más claro.

17) ¿Cómo van los comentarios en tu app.js?

A la derecha de cada línea, separados por dos espacios. Deben ser cortos y explicar qué hace esa línea concreta (entrada DOM, validación, resultado, etc.).
